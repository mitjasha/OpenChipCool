# OpenChipCool v0.3: Qu & Mudawar (2002) → CFD → 36-мм cold plate

## Фактически выполнено

- Изучена первоисточниковая статья Qu & Mudawar, IJHMT 45 (2002), DOI: https://doi.org/10.1016/S0017-9310(01)00337-4 . Геометрия и границы применимости выписаны в `qu_mudawar_openfoam_protocol.md` с номерами рисунков и страниц.
- Реализован генератор *геометрии* 21 прямоугольного микроканала 231 × 713 мкм в общей медной подложке с длиной 44,764 мм и общим габаритом 10 мм. Сгенерирован `blockMeshDict` и две зоны OpenFOAM: медь и вода.
- Написана автоматическая проверка блочной топологии: 86 блоков, 21 вход и 21 выход, 63 поверхности контакта медь–вода, ни одной потерянной внешней грани на уровне топологии блоков. Это **не** проверка утилитой `checkMesh`.
- Подготовлены уровни сетки 21 400 / 171 200 / 1 369 600 расчётных ячеек. Это **расчёт количества планируемых элементов**, а не сеточная сходимость CFD.
- Написаны исходные словари свойств, CHT и граничных условий для OpenFOAM.com v2312, с автоматической записью начальных полей после реального разделения сетки на регионы.
- Подготовлено отдельное параметрическое ядро 108-канальной пластины 36 × 36 мм, 3-мм медная база, с принятыми для примера условиями 800 Вт, 30 °C, 4 л/мин (Re приблизительно 1632). Это **предлагаемая конструкция**, а не образец статьи.
- Запущен *аналитический* контроль: потери по формуле полностью развитого ламинарного течения в прямоугольном канале и расход из заданного Re, а также энергетическая оценка повышения температуры на выходе. Построено сравнение с приблизительно снятыми с рис. 4 точками эксперимента. Это **не CFD** и не экспериментальная валидация программы.
- Все 20 автоматических тестов Python прошли на момент сборки.

## Что пока невозможно подтвердить

`blockMesh`, `checkMesh`, `chtMultiRegionSimpleFoam` и `omc` отсутствуют в среде. Никакие расчёты OpenFOAM не выполнялись. Следовательно, отсутствуют результаты CFD по перепаду давления и температуре, не выполнен GCI для CFD и не получена независимая экспериментальная валидация. Результаты CHT не переданы в FEM/RC/Modelica; старое условное выражение для HTC не заменено результатами CFD.

## Почему нельзя сравнивать одно число Δp с публикацией

Статья показывает **измеренную разность давлений между входным и выходным коллекторами**; подготовленная CFD-модель пока содержит только каналы. Для честного сравнения требуется восстановление пленумов, либо независимый расчёт входных/выходных местных потерь по их геометрии. Кроме того, в первоисточнике в расчётах учитывается изменение вязкости воды с температурой, а в нашем первом приближении вязкость постоянна. Эти ограничения нельзя скрывать коэффициентом подгонки.

## Как запускать следующий этап

```bash
python -m pip install -e '.[dev]'
pytest -q
python scripts/prepare_openfoam.py --profile paper --level coarse --Re 890 --qeff 100 --case cfd_cases/paper_Re890 --mesh
cd cfd_cases/paper_Re890
chtMultiRegionSimpleFoam > log.cht 2>&1
```

Последние две команды возможны только после установки и подключения **OpenFOAM.com**. Словари solver пока не проверены компиляцией/выполнением и могут потребовать адаптации версии. Наличие решения требует отдельной проверки residuals, массобаланса, энергобаланса, температур четырёх термопар и сравнения с данными рис. 4, 5, 7; три сетки для GCI. Полная методика — в `docs/qu_mudawar_openfoam_protocol.md`.

Для воспроизводимого самостоятельного аналитического отчёта *без* OpenFOAM:

```bash
python scripts/cfd_reference_report.py
```

Результат `results/cfd/pressure_reference_analytical_only.png` **не содержит CFD-кривых**. Ссылка на первоисточник: https://engineering.purdue.edu/mudawar/files/articles-all/2002/2002_1.pdf .
